03 · AI design & harness infrastructure

The model is the engine. I build the harness.

Anyone can call a model. Making it dependable is the work: written specs it builds against, hooks that run around every step, guardrails that fail closed, checks that gate each phase, budgets it can't exceed, and a person who signs off. It's the same discipline as standard work and poka-yoke, applied to AI.

01 · Specs

Specs before code

Every build starts as a written spec: the architecture, a phase table and acceptance checks. The model builds one phase at a time, lists every manual step for the owner, and stops for sign-off before the next.

In practice: a 16-phase app blueprint run one /phase command at a time.

harness.log · an illustrative run
  1. AI proposes, people decideThe model makes pending suggestions. Nothing changes without an accept.
  2. Fail closedAn error, a timeout or low confidence means "hold it back."
  3. Minimum contextSend only what the moment needs. Private stays private.
  4. Hard money limitsReserve the worst case before a call, settle the actual after.
  5. Write every decision downA decision log and a progress checklist let any session pick up cleanly.

Systems I've built

An AI Dungeon Master

Runs a full multiplayer Dungeons & Dragons table: writes the world, keeps the DM's secrets hidden, voices every NPC and narrates one shared story. A rules engine, not the model, owns the dice and the stats. Players say what they do, and every change to a character goes through the DM.

  • Hidden state
  • Rules engine
  • Structured outputs

A private inbox assistant

Triages email and drafts replies in my own voice. Sensitive mail is classified on my own machine and never uploaded, every upload is signed, and a read-only gateway lets an assistant search without being able to send. Only one button sends, and a person presses it.

  • Local-first
  • Fail closed
  • MCP gateway

An AI goal coach

Turns a three-to-five-year goal into small daily experiments. The AI proposes and the user accepts. Providers sit behind one interface, model choice is data rather than code, and the worst-case cost is reserved before every call, so it can never spend more than the user paid for.

  • Multi-provider
  • Credit ledger
  • Evals

A self-updating AI playbook

A daily agent compares the official model and tooling docs with yesterday's copy using plain code, and only wakes a model when something changed. A prompt hook puts the resulting best-practices log in front of each working session once a day.

  • Scheduled agent
  • Hooks
  • Near-zero cost

Autonomous, spec-driven builds

Multi-week software builds run by AI agents from a build brief, a progress checklist and a decision log. They commit at every milestone and run tests on every push, and a new session picks up from the first unchecked item.
